# Differential correctness results

## Priority 3: reference evaluator vs. the real donor

`reference_eval.py`'s `evaluate()` was run on all 250 FEN/eval pairs checked
into the donor's own repository at `test/nnue_reference.txt`, generated by
Pawnstar's own `pawnstar_eval` (bullet-side reference evaluator) for the
actual shipped `pawnstar-v12.bin` net.

This is not a synthetic or self-consistency check: it is this lab's
independent Python implementation, run against **real trained weights
downloaded directly from the donor's repository**, checked against **the
donor's own published ground truth** for that exact net.

| Metric | Result |
|---|---|
| Positions tested | 250 |
| Exact matches (0 cp) | **250 / 250** |
| Max absolute difference | 0 cp |
| Mean absolute difference | 0.0 cp |

Every single position matched exactly, including king moves across bucket
boundaries, endgames, and material-heavy middlegames (the position set is the
donor's own regression suite, so it already exercises those cases). This
confirms, independently and against real data, that the following are all
implemented correctly and bit-identically to the donor:

- Feature indexing (`FeatureRow`: bucket, colour slot, piece-type offset, square)
- King-bucket mapping (`kKingBucketMap`, file-pair x board-half)
- Perspective orientation (the `^0x38` rank flip for Black)
- SCReLU activation and its exact clamp bounds
- Side-to-move-first output concatenation
- The exact dequantisation arithmetic, including C++ truncate-toward-zero
  integer division (which required a custom `trunc_div`, since Python's `//`
  floors instead)

Reproduce with:

```powershell
.venv\Scripts\python.exe -c "
import sys; sys.path.insert(0, 'nnue_lab/teammate_pawnstar')
import chess, weights, reference_eval as ref
w = weights.load_donor_net(r'<path to pawnstar-v12.bin>')
for line in open('nnue_lab/teammate_pawnstar/nnue_reference_250.txt'):
    fen, expected = line.split('|')
    got = ref.evaluate(w, chess.Board(fen.strip()))
    assert got == int(expected), (fen, expected, got)
print('all 250 exact')
"
```

The donor weight file itself (12.6 MB) is intentionally **not** stored inside
this repository (see `PAWNSTAR_FORMAT.md` for the licence note and why) --
it lives at `%LOCALAPPDATA%\Temp\deepblue-teammate-data\donor_reference\
pawnstar-v12.bin` (SHA-256 `ee551d64a06aedd4b073bea2082d0e8d6a71981270b8e31737d2b42e2616c472`).
The 250-line reference text (15 KB) is small enough to keep in-repo and is
checked in at `nnue_reference_250.txt`.

## Priority 6: int8 (shipped) output path vs. int16 (exact) reference

`quantized.py`'s `evaluate_int8_from_board()` was compared against
`reference_eval.evaluate()` on the same real net and the same 250 donor
reference positions.

| Metric | Result |
|---|---:|
| Median absolute error | 6.0 cp |
| p95 absolute error | 18.5 cp |
| p99 absolute error | 25.5 cp |
| Max absolute error | 28.0 cp |
| Signed bias (mean) | +0.232 cp |
| Correlation (int8 vs int16) | 0.999986 |
| `output_w_scale` used | 1 (the shipped net's output weights already fit int8 -- the int8 *weight* requantisation is lossless; all approximation comes from the `>>9` activation shift) |

This closely matches the donor's own stated "~26 cp bounded deviation" for
this exact path (`PAWNSTAR_FORMAT.md` / `nnue/README.md` §1), which is a
useful independent cross-check: two different implementations of the same
quantisation spec, run against the same real weights, land on essentially
the same error profile.

## Scope note: what this does *not* cover

The donor's own `test_nnue` also validates their **int8** shipped evaluator
against `EvaluateExact` (~26 cp bounded deviation, by their own measurement).
This lab reproduces and re-measures that comparison independently (see
`quantized.py` / `BENCHMARKS.md`) rather than re-using their number
unverified.

What was **not** attempted: compiling and running the actual Pawnstar C++
engine binary locally to compare live search output. That requires a Rust
toolchain (for the `bullet` trainer/reference binary) and a C++ build chain,
which was judged out of scope for a single-session lane whose deliverable is
a Python/Numba-compatible evaluator, not a C++ engine build. The 250-position
donor ground truth was judged sufficient and higher-value evidence for the
time available: it is data the donor generated with their own reference
tooling, not a re-implementation of it.
